# Customer persona ideas

This section is appended after the existing overview. It contains three illustrative personas and expected feedback, not interview findings.

- `index.html#emma` or `#4/0`: Emma — scattered receipts and retailer rules become a prioritized task list.
- `index.html#ryan` or `#5/0`: Ryan — selective purchase input addresses concern about full-inbox access.
- `index.html#maya` or `#6/0`: Maya — mobile access is a future opportunity for instructions, receipt capture, and progress updates.

Each persona has two reveals. The existing forward/back, keyboard, hash, fullscreen, and reduced-motion logic is shared.

## Files for this section

- Persona markup and hidden Chinese speaker notes are in root `index.html`.
- `assets/personas.css` contains this section’s styles and state transitions.
- `assets/personas.js` registers these three sections.
- `assets/presentation.js` has a small extension hook so teammates can register additional sections.

The first three scenes, the product demo, and the style-guide file are preserved. The current repo does not include the original `AIPI590_pre` or `qa.html`; the current presentation is used as the working visual reference, as allowed by `PRESENTATION_STYLE.md`.

Ryan’s response is limited to selective sharing. Encryption, retention, and deletion controls are not claimed as implemented. Maya’s mobile interface is a concept, not a shipped feature.
