画面一 · 约20秒

我们关注的是需要处理多个商家退货的网购用户。比如一个学生，购买信息在邮件、小票和截图里，政策与操作步骤又在不同商家页面上。用户需要自己把这些信息拼起来，再决定先做什么。

画面二 · 约25–30秒

Return Pilot 希望将这些购买信息整理成跨商家的退货任务，结合政策和用户的选择，告诉用户现在该做什么，并持续跟进。缺少收货日期时，我们保留未确认状态，先请用户补充。我们的目标是减少查找、记忆和安排退货的负担，帮助用户及时完成必要步骤。这是体验概念，详细操作会在后面的 Web demo 展示。

Progress overview · 约45秒

Since our idea pitch, we have moved from the product concept to a clickable web prototype. First, we defined the core user journey: review a purchase, check a policy, and create a return task. Second, we implemented the frontend so users can explore tasks, prepare a return plan, and update their progress. Changes persist locally in the browser. Our next step is to connect real purchase extraction and policy retrieval, then compare rules, LLM, and hybrid planning. For this presentation, the MVP uses sample data and manual updates.

Customer persona · Emma · 约30秒

这三个人物是我们拟定的用户与反馈假设，还不是访谈结果。Emma 是经常跨商家购物的研究生。她的痛点不只是忘记截止时间，而是每次退货都要重新翻邮件、小票和政策，才能拼出商品、到货时间和操作要求。第一次点击，把同一批购买凭证变成有顺序的任务；第二次点击强调临近期限的行动，同时保留缺少日期的未确认状态。她预期会满意，因为产品减少了重复查找和自己记忆的负担。

Customer persona · Ryan · 约30秒

Ryan 是重视隐私的软件工程师。他认为产品有用，但担心为了几件退货就授权整个邮箱。第一次点击只突出订单邮件，并显示转发单封订单、上传小票和手动输入三种选择；第二次点击说明这种输入设计不要求全邮箱授权。这是后面 architecture 可以回应的具体访问范围问题，但不是已经完成的安全认证，也不代表加密、删除或数据保留机制已经实现。

Customer persona · Maya · 约30秒

Maya 是在工作与通勤之间办理退货的上班族。网页方便在家规划，但投递和查看凭证发生在外面。第一次点击出现手机端概念，用于查看步骤、拍摄凭证和更新进度；第二次点击把桌面与手机的同一批任务关联起来，作为未来扩展。最后用价值、信任、下一步三个词总结，并衔接后面的 architecture 或 future work。手机端尚未交付，图中是概念。

MVP demonstration · 约90秒

Let me show you our current web MVP. We will follow one example: returning a pair of wireless headphones. On the Today page, the user can see the next action and the approaching deadline. In purchase review, they can check and edit the purchase details before proceeding. The return task brings the deadline, estimated refund, and next step together. The plan page shows what to prepare and groups sample returns into drop-off stops. Finally, the user can update the return status and follow its progress toward a refund. These interactions demonstrate the intended user journey. Policies and locations are sample data, tracking is manual, and the AI and retailer integrations are future work.
